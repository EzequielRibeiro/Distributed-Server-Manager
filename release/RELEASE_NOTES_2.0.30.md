# Capivara DSM 2.0.30

Release focused on customer catalog hierarchy, hybrid-runtime reliability, customer file access, telemetry persistence and safer update homologation after 2.0.29.

## Customer catalog and provisioning

- Customer runtime selection now consumes the canonical hierarchical catalog instead of reconstructing editions and distributions only from flat runtime definitions.
- The customer flow explicitly exposes the distribution step while preserving canonical runtime IDs for provisioning.
- Adds regression coverage for hierarchical catalog selection and placement integration.

## Hybrid runtime reliability

- Restore the embedded Hybrid Agent CLI context and add focused regression coverage for local hybrid CLI behavior.
- Reconcile runtime permissions and local health semantics for Hybrid mode, including live adapter state reporting.
- Consume the canonical instance runtime command queue from the Hybrid worker and forward doctor/runtime actions through the canonical dispatch path.
- Persist Hybrid instance telemetry through the Controller repository path, with regression coverage for telemetry persistence.

## Customer file workspace

- DayZ runtime profile v6 exposes the private instance state root as the customer-visible `files_root`, so customer File Manager operations use instance-private data instead of only the configuration directory or shared Steam content.
- Normalize `files_root` across Linux and Windows RuntimeSpec validation with precedence: explicit `files_root`, then `instance_state_root`, then `configuration_root`, then `working_directory`.
- Add regression coverage for DayZ migration and the generic customer file-root contract.

## Update homologation

- Dedicated-server update homologation now probes the effective Dashboard endpoint from `dsm.conf`, including HTTPS installations on non-default ports.
- HTTPS health checks preserve certificate and hostname verification by resolving the configured public hostname to loopback instead of disabling TLS verification.
- Retain legacy plain-HTTP `dashboard.conf` port fallback for older installations.
- Dedicated-server homologation validated both the successful update path and the controlled rollback path, followed by a healthy HTTPS Dashboard readiness check.

## Release scope

- Includes the changes merged after v2.0.29 through PR #382 (`fix(homologation): probe effective TLS dashboard endpoint`).
- Includes PRs #372, #373, #374, #375, #376, #378, #381 and #382.
- Release artifacts, checksums and manifests remain generated by the repository Release workflow for DSM and standalone Linux/Windows Agents.
