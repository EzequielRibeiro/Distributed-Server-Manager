# Capivara DSM 2.0.31

Release focused on Hybrid runtime convergence, customer File Manager access, Universal Smart Backup and runtime/update hardening after Capivara DSM 2.0.30.

## Hybrid runtime convergence

- Reconcile embedded Hybrid runtimes periodically using the canonical Linux runtime reconciler.
- Restore customer File Manager access to private per-instance `files_root` trees without exposing those trees to unrelated users.
- Add the privileged Hybrid customer-files helper, dedicated systemd unit and constrained authorization path.
- Reconcile the Hybrid runtime substrate automatically during normal Capivara updates.
- Preserve idempotent upgrade behavior for existing Hybrid installations.

## Universal Smart Backup

- Use private per-instance roots for Linux and Windows backups, with legacy `path` fallback retained for compatibility.
- Keep shared game-data outside instance-specific backup artifacts.
- Advertise Linux backup capability.
- Reconcile canonical backup policy with Workspace defaults.
- Add Workspace-aware backup scheduling, health and `next_due_at`.
- Preserve legacy interval semantics when no Workspace schedule exists.
- Enforce canonical enablement, Workspace enablement, due-time and health gates.
- Fix PostgreSQL boolean binding in backup policy persistence.
- Process Hybrid runtime health before backup reconciliation.

## Runtime and updater hardening

- Treat Dashboard worker SIGTERM/SIGINT as controlled systemd shutdown and return success for planned stops.
- Preserve non-zero exit behavior for genuine unexpected worker failures.
- Silence transient HTTPS Dashboard readiness connection failures during successful updater retries.
- Preserve fatal timeout behavior and report the last curl error when readiness actually fails.
