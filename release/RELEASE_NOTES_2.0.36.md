# Capivara DSM 2.0.36

Patch release after Capivara DSM 2.0.35 to safely migrate legacy Capivara UFW rules into the managed firewall ownership model introduced in 2.0.35.

## Legacy UFW migration

- Detect legacy Capivara-managed UFW rules by their historical `Capivara ...` comments.
- Migrate only rules whose protocol and port exactly match the desired public runtime rule.
- Replace migrated legacy rules with canonical ownership comments in the form `capivara:<instance_id>:<name>:<protocol>:<port>`.
- Preserve idempotency when canonical managed rules already exist.
- Ensure migrated rules can later be removed safely by the instance lifecycle.

## Safety

- Never adopt or remove unrelated administrative or third-party firewall rules.
- Never migrate an entry solely because it uses the same numeric port.
- Require both protocol and port to match the desired runtime rule.
- Preserve rules using the same port with a different protocol.
- Keep cleanup scoped to the owning instance.

## Real upgrade scenario

The regression coverage reproduces the existing DayZ rules observed on the Hybrid `horizon-server` installation:

- `24000/udp` — legacy Capivara DayZ game rule
- `24002/udp` — legacy Capivara DayZ game auxiliary rule
- `24003/udp` — legacy Capivara DayZ Steam query rule

After reconciliation, those rules become canonical instance-owned managed firewall rules.

## Regression protection

The mandatory Linux managed firewall suite now covers:

- migration of legacy DayZ UFW rules;
- preservation of unrelated firewall rules;
- protocol-sensitive matching;
- canonical-rule idempotency;
- cleanup of migrated rules during instance removal.
